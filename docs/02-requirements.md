# 02. 要件

対象はステージ0（自宅 1 か所・完全紹介制・無償）。優先度は Must（試行開始に必須）/ Should（あると良い）/ Later（ステージ1 以降）。

## 1. 利用者

| 利用者 | 説明 | 利用時の状況 |
|---|---|---|
| ホスト | 自宅を開放する人。ステージ0 では 1 名 | 自分も飲んでいる、または就寝中のことがある |
| ゲスト | 紹介を受け、ホストと面談して登録された人。知人、スナックのキャストなど | 酔っている、または仕事明けで疲れている。屋外。片手でスマホ操作 |

## 2. 利用の流れ

1. **紹介と面談**：ホスト、またはホストが許可した既存ゲストが、紹介リンクを相手に送る。相手は LINE で開いて仮登録する。ホストが対面で面談し、ルールと緊急時の対応を説明して同意を取り、同宿の希望を決めて、その場で本登録にする。本登録までは申込できない。
2. **当日・開放**：ホストが「今夜は開放する」と設定する（受付時間、開ける部屋、シャワーの可否）。
3. **申込**：ゲストが空きを見て申し込む（到着予定、寝床／シャワーの希望、代行の到着見込みまたは「朝まで」、同宿の希望）。
4. **承認**：ホストに通知が届き、承認または辞退する。承認のときに部屋を割り当てる。ホストが信頼済みとしたゲストは、条件を満たせばその場で自動承認される。
5. **案内**：承認されたゲストに、住所・地図・入り方、割り当てられた部屋、困ったときの連絡先と、寝具・シャワー・トイレの使い方、ハウスルールが表示される。
6. **入室**：玄関の前でゲストが「着きました」を押すと、30 分だけ有効な暗証番号が表示される。番号で開かないときは、ホストに遠隔で解錠してもらう。
7. **滞在**：シャワーを使うときは「使用中」にする。
8. **退出**：代行が来たら、または朝になったら、ゲストが「退出」を押す。最終は 10:00。
9. **後日**：ゲストに一言アンケートが届く。ホストは利用記録を振り返る。

トラブルがあれば、ホストはどの段階でも承認の取消・退去の要請・利用停止ができる（3 章「ホストの権限」）。ゲストはいつでも理由を言わずに退出でき、滞在中の画面から助けを呼べる（3 章「困ったときの出口」）。

## 3. 機能要件

### 紹介・面談・登録

信用を第一にするため、完全紹介制とし、ホストとの対面の面談を経た人だけを登録する。

| ID | 要件 | 優先度 |
|---|---|---|

| F-02 | 紹介できるのは、ホストと、ホストが紹介を許可した既存ゲストだけ。紹介リンクは相手 1 人につき 1 本、1 回限り、有効期限つき | Must |

### 自動承認

ホストが就寝している時間帯にも受け入れられるよう、ホストがあらかじめ信頼済みとしたゲストに限り、申込を自動で承認する。

| ID | 要件 | 優先度 |
|---|---|---|
| F-90 | ホストはゲストごとに「信頼済み（自動承認の対象）」を設定・解除できる。既定は対象外。設定できるのはホストだけ | Must |
| F-91 | ホストは夜ごとに自動承認の有効・無効を切り替えられる。開放中でも即時に切り替えられる | Must |
| F-92 | 自動承認は、次のすべてを満たすときだけ行う：信頼済みである／その夜の自動承認が有効／受付時間内／同宿の決まりに合い、割り当てられる部屋がある（F-132、F-182）／同意が必要なガイドの最新版に同意済み／暗証番号で入れる場所である | Must |
| F-93 | 条件を満たさない申込は、通常の申込としてホストの承認を待つ。ゲストには承認待ちであることを表示する | Must |
| F-94 | 自動承認したことをホストに通知する。就寝中に起こさないよう、音の鳴らない通知にできる | Must |
| F-95 | 自動承認された利用も、ホストはいつでも取消・退去要請ができる（F-50〜52 と同じ） | Must |
| F-96 | 自動承認かホストによる承認かを利用記録に残す | Must |
| F-97 | 「ほかに滞在者・承認済みのゲストがいるときは自動承認しない」を設定できる | Should |
| F-98 | 信頼済みのゲストだけ、受付の締切を遅らせられる（例：通常は 3:00、信頼済みは 5:00） | Should |
| F-99 | 利用停止にしたゲスト、トラブルや注意を記録したゲストは、信頼済みを自動で解除する | Should |

遠隔解錠はホストの操作が要るため、ホストの就寝中は使えない。自動承認は暗証番号での入室が前提になる。

| F-78 | ホストはゲストごとに、各ページを読んだか・同意したかを確認できる | Should |

### 喫煙ルール

禁煙の家での喫煙は、匂いや汚れとしてホストが直接の被害を受けるうえ、酔った状態・寝床での喫煙は火災につながる。ほかのハウスルールと分けて、設定項目として持ち、見落とせない形で繰り返し提示する。

| ID | 要件 | 優先度 |
|---|---|---|
| F-100 | ホストは場所ごとに喫煙ルールを 3 つから 1 つ選ぶ：「完全禁煙」／「電子タバコのみ可」／「ベランダ・屋外でのみ喫煙可」。未設定のままでは開放できない | Must |
| F-101 | ホストは補足を書ける（例：喫煙場所、灰皿の位置、吸い殻の始末、寝床での喫煙の禁止） | Must |
| F-102 | 喫煙ルールは、文字とアイコンで、ほかのルールより目立つ形で次の場面すべてに表示する：登録時／今夜の画面／申込の画面／承認の通知／案内の画面（到着前・滞在中）／ガイドのルールページの先頭 | Must |
| F-103 | 登録時、喫煙ルールへの同意は、ほかのハウスルールとは別の操作で取る | Must |
| F-104 | 申込の画面では、申込ボタンのすぐ上に喫煙ルールを表示し、ボタンに「喫煙ルールを守って申し込む」と明記する | Must |
| F-105 | 喫煙ルールを変更したら、必ず「重要な変更」として扱う。全ゲストに通知し、次の申込の前に再同意を求める。ホストはこの扱いを外せない | Must |
| F-106 | 喫煙ルールの表示には、違反した場合は退去を求め、以後の利用を断ること、火災の危険があることを併記する | Must |
| F-107 | ホストは喫煙ルールの表示を非表示にしたり、同意を不要にしたりできない | Must |
| F-108 | トラブルの記録に「喫煙の違反」の区分を設け、1 操作で記録できる。記録すると信頼済み（自動承認の対象）を解除する | Must |
| F-109 | 室内・玄関・ベランダに貼る掲示（喫煙ルールとアイコン）を印刷できる | Should |
| F-110 | 同意の記録（誰が、どの喫煙ルールに、いつ同意したか）を、違反時の資料として書き出せる | Should |

「電子タバコのみ可」は、加熱式たばこ・電子タバコは室内で可、紙巻きたばこは不可、という意味で扱う（仮定）。

### 部屋割と同宿の配慮

ゲストが寝る部屋は最大 3 つあるが、仕切りは敷居だけで、玄関・シャワー・トイレは共用。部屋を分けても空間として切り離せないので、同じ夜に家にいるゲスト全体について、本人の希望（同宿の希望）を守る。そのうえでホストが部屋を割り当てる。

| ID | 要件 | 優先度 |
|---|---|---|
| F-180 | ホストは部屋（名前、定員、並び順、説明）を登録できる。現在は最大 3 部屋 | Must |
| F-181 | ホストは夜ごとに、開ける部屋と定員を選べる | Must |
| F-184 | ホストは、部屋の仕切りと共用部分の説明を書く（必須）。未設定では開放できない。同宿の希望を選ぶ画面と案内に表示する | Must |
| F-130 | ホストは面談のときに、ゲストの性別（女性／男性／指定なし）を登録する。同宿の配慮のためだけに使う | Must |
| F-131 | ゲストは同宿の希望を持つ：「ほかのゲストがいない夜だけ」／「同性のゲストだけなら可」（既定）／「異性のゲストがいても可」。面談のときに本人が自分の画面で選び、申込のたびに変えられる | Must |
| F-132 | 承認と自動承認は、その夜に家にいるゲスト全員の希望と、申し込む人の希望の両方に合うときだけできる。合わない申込は、ホストも承認できない。シャワーだけの利用も、家にいるゲストとして数える | Must |
| F-183 | 異性どうしを同じ部屋にしない。性別が「指定なし」の人は、ほかの人と同じ部屋にしない。部屋の定員を超えない。同宿の希望が「異性のゲストがいても可」でも同じ | Must |
| F-182 | 寝床を希望する利用の承認のとき、部屋を割り当てる。システムが決まりに合う部屋を候補に出し、ホストは決まりに合う部屋の中から選び直せる。自動承認ではシステムが決める | Must |
| F-133 | 同宿の希望をゆるめる変更はいつでもできる。きびしくする変更は、いまの顔ぶれと合うときだけできる | Must |
| F-134 | 申込の前に、寝床とシャワーそれぞれについて、今夜申し込めるかを表示する。申し込めない理由は、「今夜の受け入れ設定」「自分の同宿の希望」「ほかの滞在者の希望、または部屋の空き」のどれかだけを伝える | Must |
| F-135 | 承認されたゲストに、今夜の滞在者の人数と男女の内訳、同じ部屋に人がいるかを伝える | Must |
| F-185 | 承認されたゲストに、割り当てられた部屋とその説明を表示する | Must |
| F-136 | ホストは夜ごとに、受け入れを「指定なし／女性のみ／男性のみ」から選べる | Should |

### 困ったときの出口

利用の可否はホストが決め、ゲストは異議を出せない（F-57）。それとは別に、ゲストがいつでも退出でき、助けを呼べる手段を用意する。

| ID | 要件 | 優先度 |
|---|---|---|
| F-120 | 承認後の案内と滞在中の画面に「困ったとき」の欄を常に表示する。内容：いつでも理由を言わずに退出できること、119・110 への発信、119 番で伝える住所、ホストの緊急用の電話（設定時）、「困っています」、夜間に移れる場所、ホスト以外の相談先（設定時） | Must |
| F-121 | ホストは、緊急用の電話番号、夜間に移れる場所、ホスト以外の相談先を設定できる | Must |
| F-122 | 承認済み・滞在中のゲストは「困っています」を 1 操作で送れる。種類（体調／ほかの人のこと／設備／その他）は任意。ホストに音の鳴る通知を送り、記録する | Should |
| F-123 | ホストが「確認した」を押すまで再送する（間隔と回数に上限）。ゲストの画面に、確認の状況と、急ぐときは電話する旨を出す | Should |
| F-124 | 退出後のアンケートに「困ったこと」の欄を設ける | Should |

## 5. 権限の限界

- システムが特定できるのは LINE アカウントまでで、本名や住所は保存しない。相手の本名や連絡先は、面談のときにホストが直接確認し、必要ならホストだけが見られる面談メモに控える。
- システムは喫煙そのものを検知できない。できるのは、ルールの提示・同意の記録・違反後の対処まで。火災警報器の設置や灰皿の管理は、システムの外でホストが行う。
- 部屋の仕切りは敷居だけで、玄関・シャワー・トイレは共用。システムは同宿の希望と部屋割を守るが、空間として切り離すことはできない。
- システムはゲストの体調を見守れない。ホストも寝ていることがある。できるのは、受け入れない状態の明示、緊急時の案内、助けを呼ぶ手段の表示まで。
- ホスト自身とのトラブルについて、申告を受けて裁定する第三者は置けない。ホスト以外の相談先を案内するにとどまる。
- 発行済みの暗証番号は、取り消した後も最大 30 分は有効なままになりうる（鍵の API で番号を削除できない不具合の報告があるため。04-lock-selection.md）。

## 6. ステージ0 で扱わない要件

課金、身分証による本人確認、公開の相互評価、第三者による申告の受付と裁定、保険、屋内のカメラや喫煙の検知センサー、定時の安否確認、代行業者との連携、アルコールが抜けたかの判定、ネイティブアプリ、多言語対応。
