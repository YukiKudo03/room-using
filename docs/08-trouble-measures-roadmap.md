# 08. トラブル対策の組み込み方針とロードマップ

作成日：2026-11-18。同日、7 章の決定を受けて更新した。

[07 類似サービスのトラブル対策の調査](07-trouble-prevention-review.md) の提案を、いまの段階（ステージ0、実装前）のシステムにどう組み込むかを検討した。7 章の点が決まったので、要件（02）、設計書（03 の版 1.1）、ハウスルール第 1 版の案（09）に反映してある。

決定の中で、部屋は最大 3 つあり、仕切りは敷居だけで、出入り口は共通であることが分かった。これを受けて、4.2 は「同じ部屋になる相手」ではなく「同じ夜に家にいるゲスト」と部屋割の話として書き直している。これに合わせ、用語を「同室の希望」から「同宿の希望」に改めた。

## 1. 結論

- 07 の 7 つの提案のうち、**6 つは中心になる部分を試行の前に入れる**。残る 1 つ（注意の段階）は試行が始まってからでよい。ホストどうしの論点は、ホストを増やす判断のときに決める。
- 入れるものの大半は、**文面（ハウスルール）と設定項目**で済む。機能として作るのは主に「同宿の希望と部屋割」と「困っています」の 2 つで、ほかは既にある仕組みを広げれば足りる。
- **最初の 1 人を登録する前に確定させる**。ゲストの性別と同宿の希望は面談で聞く項目で、ハウスルールは面談で同意を取る文面なので、あとから足すと全員に聞き直すことになる。
- 設備と運用の準備（火災警報器、緊急時の備え、相談先）は、システムの外でホストが行う。試行を始める条件に含める。

## 2. 判断の軸

何をいま入れ、何を後に回すかを、次の 3 点で決めた。

| 軸 | 内容 | あてはまるもの |
|---|---|---|
| 取り返しがつくか | 命、性被害、火災は、1 度起きたら取り返しがつかない。起きる頻度が低くても試行の前に備える | 泥酔時の安全、同宿の配慮、緊急時の出口、火災警報器 |
| 後から足すとやり直しが出るか | 面談で聞く項目と、同意を取る文面は、最初の登録より前に要る | 性別と同宿の希望、ハウスルール第 1 版 |
| 試行で確かめたいことに響くか | キャストが安心して使えなければ、需要があるかどうか自体を確かめられない | 同宿の配慮、困ったときの出口、カメラを置かない旨の明示 |

費用は、文面 ＜ 設定項目 ＜ 機能 ＜ 設備 の順に大きい。同じ効果なら小さい方を選んだ。

## 4. どう組み入れるか

設計の詳細は設計書（03）の 6.11〜6.13 にある。ここでは考え方を述べる。

### 4.1 困ったときの出口（項目 1〜4）

承認後の案内画面と、滞在中の画面に、「困ったとき」の欄を常に出す。

| 表示 | 内容 |
|---|---|
| 退出 | 「いつでも、理由を言わずに退出できます」 |
| 119・110 | 押すと発信する |
| 住所 | 「119 番で伝える住所」として表示する |
| ホストに電話 | ホストが緊急用の番号を設定したときだけ出す |
| 困っています | 下に述べるボタン |
| 夜間に移れる場所 | ホストが書く（近くの 24 時間営業の店、タクシー会社の番号など） |
| ホスト以外の相談先 | ホストが設定したときだけ出す |

**電話を主、ボタンを従とする。** LINE の通知音は短く、寝ているホストが気づくとは限らない。急ぐときは電話、という順序を画面でも伝える。

**「困っています」ボタン**：1 回押すだけで送れる。種類（体調／ほかの人のこと／設備／その他）は任意。ホストに音の鳴る通知を送り、ホストが「確認した」を押すまで数分おきに再送する。ゲストの画面には、確認されたかどうかと、「急ぐときは電話してください」を出す。送った時刻と確認した時刻を記録する。

**ホスト自身とのトラブル**：このボタンは役に立たない。出口は、退出すること、110 番、ホスト以外の相談先になる。相談先は、外部の人に頼む方向で調整する。頼むときに取り決めておくことは次のとおり。

- 連絡の手段と、受け付ける時間帯（深夜に出られるか）
- 聞いた内容を、本人の同意なしにホストへ伝えないこと
- してもらうこと：話を聞く。必要なら 110 番・119 番を勧める。本人が望めばホストに伝える
- してもらわないこと：どちらが正しいかの判断、利用の可否の判断

ステージ0 では、申告を受けて裁定する第三者は置けない。この限界は面談で率直に説明する。

**方針との関係**：利用の可否はホストが決め、ゲストは異議を出せない（F-57）。この方針は変えない。安全のための出口は、それとは別に用意する。

### 4.2 同宿の配慮と部屋割（項目 5〜7）

面識のない人どうしが、酔った状態で、ホストが寝ている間に同じ家で寝る。ここが最も重い事故につながりうる。

**前提**：ゲストが寝る部屋は最大 3 つ。仕切りは敷居だけで、鍵はかからない。玄関、シャワー、トイレは共用。部屋を分けても、空間として切り離すことはできない。

**考え方**：部屋が別でも隔離にはならないので、「部屋が別なら、面識のない異性がいても構わない」とは扱わない。同じ夜に家にいるゲスト全体について、本人の希望を守る。部屋割は、そのうえでの配慮として使う。

| 層 | 内容 | 決める人 |
|---|---|---|
| 同宿の希望（家全体） | ほかのゲストがいない夜だけ／同性のゲストだけなら可（既定）／異性のゲストがいても可 | ゲスト本人 |
| 夜ごとの受け入れ | 指定なし／女性のみ／男性のみ | ホスト |
| 部屋割 | どの部屋を開け、誰をどの部屋にするか。異性どうしは同じ部屋にしない | ホスト（候補はシステムが出す） |

- **既に承認された人の希望は、本人が変えない限り守る。** 決まりに合わない申込は、ホストでも承認できない。ホストが受け入れたいときは、既にいる人に直接頼み、本人が希望を変える。
- シャワーだけの利用も、家にいるゲストとして数える。玄関とシャワーが共用のため。
- 「異性のゲストがいても可」を選んだ人どうしでも、部屋は必ず分ける。
- 部屋の仕切りと共用部分の説明を、ホストが必ず書く。ゲストが同宿の希望を選ぶ画面に出す。仕切りが敷居だけであることを知ったうえで選んでもらうため。
- 承認前のゲストには、これまでどおり人数だけを見せる。承認されたゲストには、部屋、人数と男女の内訳、同じ部屋に人がいるかを伝える。あとから人が加わったら知らせる。
- 操作の数は増やさない。申込の画面に同宿の希望の行を足すが、既定が選ばれた状態で出す。

**削る場合の最小の形**：「性別が違う人、または指定なしの人がいる夜は受け入れない」という固定の決まりと、部屋を 1 人 1 部屋で順に割り当てる処理だけにする。同宿の希望の選択肢と、夜ごとの設定は省ける。性別の登録だけは最初から必要。

**設備で補えること**：部屋の入口に戸や間仕切りを付ける、部屋の名前を室内に表示する。仕組みの代わりにはならないが、安心感は上がる。

### 4.3 泥酔時の安全（項目 8、9）

**ハウスルールに書き、同意を取ること**

- 受け入れない状態：自分で歩けない、呼びかけに応じない、吐き続けている。この状態の人は申し込まず、119 番に通報する。
- ホストは寝ていることがあり、見守りはしない。深酒のときは利用しない。
- 家にいる人の様子がおかしいときは、119 番に通報し、ホストに知らせる。

「見守りはしない」は、ゲストにとって危険の説明にあたる。面談で口頭でも説明し、チェック項目に入れる。

**「緊急時」の固定ページ**：喫煙ルールと同じ仕組みにする。先頭はシステムが出す定型文で、ホストは補足（バケツの場所、近くの救急病院など）だけを書ける。削除も非表示もできない。「困ったとき」の欄と、ガイドの切り替えから開ける。室内に貼る QR コードからも開ける。

定型文の内容は、大学が学生向けに出している飲酒事故防止の資料で確認できた（文面と出典は 09）。

- 介抱のしかた：絶対にひとりにしない。衣服をゆるめる。毛布などで体温が下がるのを防ぐ。吐いた物がのどに詰まらないよう横向きに寝かせる。吐きそうなときは抱き起こさず、横向きのまま吐かせる。
- 迷わず 119 番にかける目安：体が冷たくなっている。名前を呼んでも体をゆすっても反応がない。息苦しそうにしている。大いびきをかいている。口から泡を吹いている。大量に血を吐いた。

横向きに寝かせる姿勢（回復体位）の細かい手順は確認できていない。救命講習で確かめる。

**朝の通知**：10:00 に残っているゲストをホストに知らせる通知（F-42）は、安否の確認を兼ねる。通知に「様子を確認してください」と入れる。

**ホスト側の準備（システムの外）**

- 救命講習を受ける。消防の普通救命講習は 3 時間程度で、心肺蘇生、AED、異物の除去などを扱う。受講料が無料の自治体がある。日程と料金は管轄の消防署に確認する。
- 備品を置く：バケツ、防水のシーツ、飲み水、汚れた寝具の替え。

**やらないこと**：一定の時間ごとにゲストへ呼びかけて、返事がなければホストに知らせる仕組み。寝ている人は返事をしないので誤報が続き、ホストも寝ているので役に立たない。

### 4.4 カメラとセンサー（項目 10、11、18）

- ハウスルール第 1 版に、屋内にカメラと録音機器を置いていないことを書く。寝床とシャワーを貸す以上、信用の土台になる。
- 玄関の外にカメラを置く場合は、その場所を書く。センサーを置く場合は、種類と場所を書く。
- 設計書の方針に「システムは屋内の映像と音声を扱わない」を加えた。
- 火災警報器：寝室や階段などへの設置は、各自治体の火災予防条例で義務づけられている。ゲストが寝る部屋のそれぞれに付いているかを確かめる。作動の確認は年 1 回以上、設置から 10 年を過ぎたものは交換する。
- 喫煙の検知センサーは見送る。性能を確認できておらず、加熱式・電子タバコを検知できるかも分からない。試行で喫煙の違反が起きたら再検討する。

### 4.5 ハウスルール第 1 版（項目 12、13）

面談で同意を取るので、最初の面談より前に用意する。あとからの変更は、再同意の仕組みで対応できる。文面の案は [09](09-house-rules-v1.md) にある。

| 章 | 内容 |
|---|---|
| 利用の前提 | 申込のたびに承認が要る。登録していない人を連れてこない。朝 10:00 までに退出する |
| 喫煙 | 喫煙ルールのページのとおり |
| 体調と安全 | 受け入れない状態。ホストは見守りをしない。様子がおかしい人がいたら 119 番とホストへの連絡 |
| 部屋とほかのゲスト | 部屋の仕切りと共用部分。同宿の希望の仕組み。ほかの人の部屋と持ち物に触れない |
| 過ごし方 | 静かにする時間。室内で追加の飲酒をしない。使った後の片付け。共用の場所に私物を残さない。貴重品は自分で管理する |
| 設備 | 屋内にカメラ・録音機器はない。屋外カメラとセンサーの有無と場所 |
| ホストの判断 | ホストの指示に従う。従えないときは退去を求め、以後の利用を断る。破損・汚損・喫煙による清掃は、実費を請求することがある |
| 記録 | 利用の記録と同意の記録を保管する。登録を解除した後も保管する |
| 困ったとき | いつでも退出できる。連絡先 |

### 4.6 注意の段階（項目 15）

トラブルの記録（F-58）を広げて作る。

- ホストが「注意」を選び、区分（騒音、片付け、時間、その他）とメモを入れると、ゲストに定型の通知が届く。
- 注意を受けたゲストは、信頼済み（自動承認の対象）から外れる。ホストはあとで戻せる。
- 注意の回数を、ゲスト一覧と申込の通知に表示する。

軽い違反は試行が始まってから分かるので、急がない。

### 4.7 やらないこと

| 項目 | 理由 |
|---|---|
| 屋内のカメラ・録音 | 信用を損なう。類似サービスでも禁止されている |
| 定時の安否確認 | 4.3 のとおり、誤報が続き役に立たない |
| 承認前のゲストへの男女の内訳の表示 | 4.8 のとおり |
| 損害の補償、保険 | 無償・個人の運営では持てない。有償化の段階で検討する |
| 公開の相互評価 | 紹介と面談で相手を確かめているので、利点が小さい。顔見知りの小さな集まりでは、率直に書きにくい |
| 他のホストとの情報共有への同意 | いまは取らない。再同意の仕組みがあるので、ホストを増やすときに条項を足せる |

### 4.8 検討の途中で変えた点

| 以前の案 | いまの扱い | 理由 |
|---|---|---|
| 申込の画面に、滞在者の人数と男女の内訳を出す（07） | 承認前は人数だけ。内訳は承認された人にだけ伝える | 過去に利用した人は住所を知っている。「いま女性が 1 人で寝ている」ことを登録者全員に見せるのは避ける |
| 「ほかの人がいるなら見送る」を申込のときに選ぶ（07） | 「ほかのゲストがいない夜だけ」という希望にして、承認の条件に組み込む | 申し込んだ時点だけでなく、あとから来る人に対しても効くようにする |
| 「困っています」ボタンでホストに知らせる（07） | 電話を主、ボタンを従にする | 通知では寝ているホストが気づかないことがある |
| 2 つの寝床が同じ部屋にある前提で、「同じ部屋になる相手」の希望を扱う（本書の初版） | 最大 3 部屋の部屋割を加え、希望は家全体について守る | 部屋の仕切りは敷居だけで、玄関・シャワー・トイレが共用のため、部屋を分けても隔離にならない |

## 5. ロードマップ

期間は実装に充てられる時間で変わるので、順序と、各段階を終える条件を示す。

### 5.1 全体

| 段階 | 内容 | 終える条件 | 状況 |
|---|---|---|---|
| A 設計の確定 | 7 章の点を決める。要件・設計書・モックに反映する。ハウスルール第 1 版と「緊急時」ページの文面を書く | 文面と要件が確定している | 決定と反映は済み。文面は案を作成済みで、ホストの確認待ち |
| B 実装 | 設計書の実装の順序（03 の 14 章）に、5.2 のとおり組み込む | 5.3 のシステムの項目を満たす | 未着手 |

### 5.2 実装の順序への組み込み

| 03 の段階 | もともとの内容 | 足すもの |
|---|---|---|
| 1 | LINE ログイン、紹介、仮登録、面談、本登録 | 性別と同宿の希望の登録。面談のチェック項目の追加（部屋の仕切りと同宿の希望、緊急時の対応と連絡先）。面談したホストの記録 |
| 2 | ガイド、喫煙ルール | 固定ページの仕組みを喫煙専用にせず共通にして、「緊急時」ページを足す。ハウスルール第 1 版を初期の内容として入れる |
| 3 | 開放設定、今夜、申込、承認、案内 | 場所と部屋の設定。夜ごとに開ける部屋と受け入れ設定。申込の同宿の希望。承認時の決まりの確認と部屋の割り当て。「困ったとき」の欄 |
| 4 | 鍵の連携、到着・退出 | なし |
| 5 | 通知、定時処理、監査ログ | 「困っています」の通知と再送。新しく承認された人の通知。10:00 の通知の文言 |
| 6 | ホストの権限、記録 | 注意の記録と通知。部屋の変更。試行で見る指標 |
| 7 | 自動承認、紹介の可否 | 自動承認の条件に、同宿の決まりと部屋の割り当てを足す |

段階 1 と 2 に入るものは、あとから足すとやり直しが出る。段階 5 と 6 に入るものは、間に合わなければ試行の開始後に回せる。

### 5.3 試行を始める条件

**システム**

- [ ] 「困ったとき」の欄が、案内と滞在中の画面に出る（退出できること、119・110、住所）
- [ ] 同宿の決まりと部屋割が、承認と自動承認の両方で守られる
- [ ] 「緊急時」と喫煙ルールのページが、消せない形で表示される
- [ ] ハウスルール第 1 版に同意しないと、本登録にできない
- [ ] 協力者 1 人と通しで確認する：紹介 → 面談 → 申込 → 入室 → 困っています → 退出、ホストによる承認の取消

**設備と運用**

- [ ] 火災警報器が、ゲストが寝る部屋のそれぞれで作動する
- [ ] 緊急時の備品を置いた
- [ ] 部屋の名前を、室内に表示した
- [ ] 部屋の仕切りと共用部分の説明、ホストの緊急用の電話番号、夜間に移れる場所を設定した
- [ ] 外部の相談先と、頼む内容（4.1）を取り決めて設定した
- [ ] 喫煙ルールと緊急時の掲示を貼った
- [ ] 貴重品の置き場を決めた
- [ ] ハウスルール第 1 版の [ ] の箇所を埋め、面談で話す順序を確かめた（09）
- [ ] 救命講習を受けた（推奨）

鍵の実機の確認（04 の 4 章）と、バックアップからの復元の確認（06 の 6 章）も、試行を始める条件に含まれる。

### 5.4 試行中に見る指標

| 指標 | 見ること | 次の手を考えるきっかけ |
|---|---|---|
| 「困っています」の件数と、確認までの時間 | ホストが気づけているか | 確認が遅い → 電話の案内を強める、相談先を見直す |
| 同宿の決まりで申し込めなかった件数 | 決まりがきつすぎないか | 多い → 夜ごとの受け入れ設定を使う。部屋の入口に戸を付けるなど、仕切りを強める |
| 注意、退去の要請、利用停止の件数 | どんな違反が起きるか | 同じ種類が続く → ハウスルールの文面と面談の説明を直す |
| 喫煙の違反 | 表示と同意で足りているか | 1 件でも → 検知センサーを再検討する |
| 119 番・110 番に至った件数 | 受け入れの基準が守られているか | 1 件でも → 試行をいったん止めて、基準と運用を見直す |
| アンケートの「困ったこと」 | 表に出にくい不満 | 内容による |

### 5.5 ステージ1 に進むときに決めること

| 論点 | いまの備え |
|---|---|
| ホスト自身に関する申告を受ける第三者 | 外部の相談先（4.1）が、その前段になる |
| 利用停止の名簿をホスト間で共有するか | 共有の同意は、再同意の仕組みで後から取れる。個人の情報を他人に渡すことになるので、専門家に確認する |
| 全ホスト共通の必須項目 | 固定ページの仕組みを共通にしてあるので、喫煙・緊急時・設備の開示を全ホストに課せる |
| 面談を他のホストも有効と見なすか | 面談したホストを記録している |
| ゲストからホストへの評価 | アンケートの「困ったこと」を、ホスト間で見られるようにするかを決める |
