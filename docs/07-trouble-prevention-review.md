# 07. 類似サービスのトラブル対策の調査

調査日：2026-11-18。

類似サービスが、ホストとゲストの間、ゲストどうし、ホストどうしのトラブルにどう備えているかを調べ、本システムの設計（[03 設計書](03-system-design.md)）と照らし合わせた。

## 1. 調査の範囲と限界

| 種類 | 調べたサービス | 本システムとの共通点 |
|---|---|---|
| 民泊 | Airbnb | 個人の家に他人を泊める。ホストとゲストの信頼の仕組みが最も整っている |
| 無償の宿泊交換 | Couchsurfing、BeWelcome、Trustroots、Warmshowers | 無償で自宅に泊める。お金のやり取りがなく、信頼だけで成り立つ |
| 相部屋の宿 | ホステル、ゲストハウス（ドミトリー） | 面識のない人どうしが同じ部屋で寝る |
| 共同の住まい | シェアハウス | 共用の設備（風呂・トイレ）を分け合う |
| 時間貸し | スペースマーケット | 数時間の場所貸し |
| 多拠点居住 | ADDress | 会員制で、各拠点に管理者（家守）がいる |

限界：

- 多くは検索結果の要約に基づく。各社の公式ページを直接読めたものは少ない。
- **スペースマーケットと ADDress は、具体的な対策をほとんど確認できなかった。** 本書では材料にしていない。
- BeWelcome・Trustroots・Warmshowers は公式の安全対策のページを確認できず、利用者の投稿などの二次情報にとどまる。
- 喫煙の検知センサーの情報は、センサーの販売元の記事が中心で、性能の第三者による検証は見つからなかった。
- 法律に関わる記述（個人情報の共有など）は一般的な注意であり、専門家の確認を経ていない。

## 2. 本システムに特有の事情

類似サービスの対策をそのまま当てはめられない点がある。

- **ゲストは酔っている。** 判断力が落ち、体調が急変することがある。類似サービスにこの前提のものはない。
- **ホストは寝ていることがある。** 自動承認と暗証番号で、ホストが起きないまま人が出入りする。
- **運営者とホストが同じ人。** Airbnb や Couchsurfing では、運営会社が第三者として通報を受け、裁定する。本システムにはその第三者がいない。
- **無償。** 補償や清掃費を運営が立て替える仕組みを持てない。
- **紹介と面談を経ている。** 匿名の相手ではない。類似サービスの本人確認より強い面がある。

## 3. ホストとゲストの間

### 3.1 類似サービスの対策

| 対策 | 採用例 | 内容 |
|---|---|---|
| 本人確認 | Airbnb | 政府発行の写真つき身分証による確認を、ホストとゲストの両方に課す |
| 確認済みの表示 | Couchsurfing | 本人確認を済ませた会員に印を付ける。本人であることの確認で、行いの保証ではないと明記 |
| 相互の評価 | Airbnb、Couchsurfing、Warmshowers | 滞在後にお互いを評価し、公開する。次の相手が判断材料にする |
| 非公開の申告 | Couchsurfing | 相手に見えない形で運営にだけ伝える評価。通報は秘密として扱う |
| 予約の事前の選別 | Airbnb | 迷惑行為や破損のおそれが高い予約を自動で止める |
| 基本ルールと段階的な処分 | Airbnb | ゲスト共通の基本ルール（ハウスルールを守る、清潔に使う、破損しない）。違反は警告、繰り返すと利用停止・退会 |
| ハウスルールの定型項目 | Airbnb | 喫煙、静かにする時間、人数の上限などを選択式で設定 |
| パーティーの全面禁止 | Airbnb | 全物件で禁止（2022 年に恒久化） |
| 損害の補償 | Airbnb | ホストの損害を運営が保証（最大 300 万米ドル） |
| 実費の請求 | Airbnb | 破損・紛失・追加清掃の実費を、証拠（写真、請求書、検知記録）を添えて請求。喫煙の清掃費は、ルールを明示し違反を証明できれば請求できる |
| 屋内カメラの禁止 | Airbnb | 屋内を監視するカメラ・録画機器は、電源が切れていても不可。屋外カメラは場所を開示すれば可 |
| 騒音計の開示 | Airbnb | 屋内の騒音計は、存在を開示すれば可。寝室・浴室には置けない |
| 喫煙の検知センサー | 民泊向け製品 | カメラも録音もなしに喫煙を検知してホストに知らせる、と販売元は説明。設置を物件の説明に明記することを推奨 |
| 会う前の見極め | Couchsurfing | 相手の評価と人となりを確認し、共通の知人に尋ねる |
| 代わりの宿の確保 | Couchsurfing | 合わなければすぐ出られるよう、別の宿泊先を用意しておく。近くの宿を探す機能がある |
| 緊急時の順序 | Couchsurfing | 危険が迫るときは、まず警察・救急へ。運営への報告はその後 |

### 3.2 本システムとの対応

| 対策 | 本システム | 状況 |
|---|---|---|
| 本人確認 | 紹介と対面の面談。面談メモに本名・連絡先 | 採用済み（身分証の確認より人のつながりに重きを置く） |
| ゲストへの評価 | 利用記録、トラブル記録、信頼済みの設定 | 採用済み（ホストだけが見る） |
| ホストへの評価・申告 | 一言アンケートのみ。異議の手段は置かない（F-57） | **不足**（5 章の提案 1） |
| 予約の選別 | 毎回の承認、自動承認の条件 | 採用済み |
| 段階的な処分 | 承認取消・退去要請・利用停止。警告にあたる段階はない | 一部（提案 6） |
| ハウスルール・喫煙 | ガイド、喫煙ルールの設定と繰り返しの提示、版つきの同意 | 採用済み（類似サービスより強い） |
| 人数・同行者 | 登録していない同行者は不可。番号は 30 分で切れる | 採用済み |
| 損害の補償 | なし（無償・個人運営） | 対象外。実費請求の予告は提案 7 |
| 証拠の保全 | 監査ログ、同意の記録、写真つきトラブル記録、書き出し | 採用済み |
| カメラ・センサー | 定めなし | **不足**（提案 4） |
| 緊急時の案内 | 定めなし | **不足**（提案 3） |
| 途中で帰れること | 定めなし | **不足**（提案 1） |

## 4. ゲストどうし

### 4.1 類似サービスの対策

| 起きること | 対策 | 採用例 |
|---|---|---|
| 異性と同室になる不安、嫌がらせ | 女性専用の相部屋。相部屋の扉の施錠、カード式の入室。嫌がらせへの対処と結果をルールに明記 | ホステル |
| 盗難 | 鍵つきのロッカー。私物を共用の場所に置かない | ホステル、シェアハウス |
| 騒音、いびき | 静かにする時間（例：22〜23 時から 7〜8 時） | ホステル |
| 酒によるもめごと | 相部屋での飲酒は禁止し、飲める場所を共用部に限る | ホステル |
| 見知らぬ人の出入り | 宿泊者以外は相部屋に入れない | ホステル |
| 風呂・トイレの使い方 | 利用時間、使った後の片付けのルール。清掃・ごみ出しのルール | シェアハウス |
| 私物の放置 | 共用部に私物を置かないルール | シェアハウス |

国土交通省の調査では、シェアハウスの入居者間のトラブルは「ない」が 4 割強で最も多い。起きるものでは、騒音と、共用部への私物の放置が 2〜3 割を占める。

### 4.2 本システムとの対応

| 対策 | 本システム | 状況 |
|---|---|---|
| 同室になる相手の配慮 | ほかに滞在者がいる夜は自動承認しない。ホストが承認する相手を選ぶ。ゲストには人数だけを見せる | 一部（提案 2） |
| 同性だけの夜 | 定めなし | **不足**（提案 2） |
| 貴重品の保管 | 定めなし | **不足**（提案 5） |
| 静かにする時間 | ガイドに書ける（モックに「深夜はドライヤー不可」の例） | ホストの記載に任せている（提案 5） |
| 室内での飲酒 | 定めなし | **不足**（提案 5） |
| シャワーの順番 | 「使用中／空き」の表示 | 採用済み |
| ゲスト間のもめごとの申告 | 定めなし | **不足**（提案 1） |

## 5. 提案

優先度は、起きたときの重さと、本システムに特有かどうかで付けた。

### 提案 1（高）：ゲストが困ったときの出口を用意する

類似サービスは、運営という第三者が通報を受ける。本システムはホストが運営者なので、ホストとのトラブルや、ホストが寝ている間のゲスト間のトラブルで、ゲストに頼る先がない。キャストなど立場の弱いゲストが含まれるので、ここは空白にしない方がよい。

- 案内画面と面談時の説明に、次を明記する：いつでも理由なく退出できる／身の危険を感じたら 110 番・119 番／夜間に移れる近くの場所（タクシー、24 時間営業の店など）。
- 滞在中の画面に「困っています」ボタンを置き、ホストに音の鳴る通知を送る。ほかのゲストとのトラブルも想定する。
- 退出後のアンケートに「困ったこと」の欄を加える。
- ホスト自身に関する申告を受ける第三者は、ステージ0 では置けない。紹介者に相談できることを案内するにとどめ、ホストが複数になる段階で第三者の窓口を設ける。

F-57（ホストの決定に異議を出す手段を置かない）は変えない。利用の可否はホストが決める、という点と、安全の出口は別の話として両立する。

### 提案 2（高）：同室になる相手を、ゲストも選べるようにする

ホステルの女性専用の相部屋にあたる仕組み。

- ホストが夜ごとに「女性のみ」「男性のみ」「指定なし」を選べる。
- ゲストは申込のときに「ほかの人がいるなら見送る」「同性だけなら可」を選べる。
- 申込の画面に、いまの滞在者の人数と男女の内訳を出す（名前は出さない）。
- 承認済みのゲストに、あとから別の人が加わったときは知らせる。

このためにゲストの性別を持つ必要がある。面談のときにホストが登録する形にする。

### 提案 3（高）：泥酔したゲストの安全

酔った人を受け入れることに特有の危険で、類似サービスに手本がない。厚生労働省と消防の資料によれば、急性アルコール中毒では、呼吸の中枢が抑えられる場合と、吐いた物で窒息する場合に死亡することがある。本人が苦しさを感じないまま進むこともある。

- **受け入れの基準**をハウスルールに書く：自分で歩けない、呼びかけに応じない、吐き続けている人は受け入れず、同行者またはホストが 119 番に通報する。
- **緊急時のページ**をガイドに固定で置く：横向きに寝かせる、一人にしない、意識がない・呼吸がおかしいときは 119 番。住所をその場で伝えられるよう、滞在中のゲストには画面に住所を出す。
- **ほかのゲストへの案内**：同室の人の様子がおかしいときは「困っています」ボタンと 119 番。
- ホストが寝ている間は見守りができない。この点は面談で説明し、深酒のときは利用を控えるよう伝える。

応急処置の具体的な手順は今回の調査で確認できていない。ページの文面は、消防や自治体の公式資料に基づいて作る。

### 提案 4（中）：カメラとセンサーの扱いを決める

Airbnb は、屋内のカメラを電源が切れていても禁止し、屋外カメラと騒音計は開示を条件に認めている。寝室と浴室にはどちらも置けない。

- 屋内にカメラ・録音機器を置かないことを、ハウスルールに明記する。寝床とシャワーを貸す以上、ここは信用の土台になる。
- 玄関の外にカメラを置く場合は、場所をガイドに明記する。
- 喫煙の検知センサーは、置くなら存在を明記する。カメラも録音もなしに検知できると販売元は説明しているが、性能は確認できていない。加熱式・電子タバコを検知できるかも不明。
- 住宅用の火災警報器が寝床と台所にあることを確かめる。

### 提案 5（中）：ハウスルールの定型項目を増やす

いまは喫煙だけが設定項目で、ほかはホストの自由記述になっている。類似サービスで定番の項目を、初期のハウスルールに入れておく。

- 静かにする時間
- 室内で追加の飲酒をしない
- 貴重品は自分で管理する。鍵つきの箱や棚があればその場所
- ほかのゲストの寝床・持ち物に触れない
- 共用の場所に私物を残さない
- 使った後の片付け（シャワー、トイレ、寝具）

鍵つきの保管場所は、設備として用意するかをホストが決める。

### 提案 6（低）：警告の段階を加える

Airbnb は警告から始め、繰り返すと利用停止にする。本システムは退去要請と利用停止だけで、軽い違反に使える段階がない。

- ホストが「注意」を記録し、ゲストに通知できるようにする。信頼済みは解除する。
- 注意の回数をゲスト一覧と申込の通知に表示する。

ホストの裁量を狭めるものではなく、軽い違反の記録を残すための手段として加える。

### 提案 7（低）：実費の請求を予告する

Airbnb は、破損・紛失・追加清掃の実費を、証拠を添えて請求する仕組みを持つ。本システムは無償だが、ハウスルールに「破損・汚損・喫煙による清掃は実費を請求することがある」と書いておくと、同意の記録が請求の根拠の一つになる。請求そのものはシステムの外でホストが行う。

## 6. ホストどうし（ステージ1 以降）

ステージ0 はホストが 1 人なので、いまは起きない。ホストを増やすときに決めることを挙げる。類似サービスで確認できた材料は少ない。

| 論点 | 類似サービスの例 | 検討事項 |
|---|---|---|
| 問題のあった相手の情報の共有 | Airbnb と Vrbo は、規約違反で除外した物件を両社で特定する取り組みを発表（2021 年、米国）。対象は物件 | ホスト間で利用停止の名簿を共有するか。共有するなら、何を根拠に載せ、本人にどう伝えるか。個人の情報を第三者に渡すことになるので、同意の取り方を含め専門家に確認する |
| ルールの最低基準 | Airbnb はゲスト共通の基本ルールと、全物件共通の禁止事項を持つ | 喫煙の表示、カメラの禁止、緊急時の案内などを、全ホスト共通の必須項目にする |
| 面談の扱い | — | あるホストの面談を、ほかのホストも有効と見なすか。ホストごとにやり直すか |
| 紹介の責任 | — | あるホストの紹介したゲストが別のホスト宅で問題を起こしたときの扱い |
| ホストへの申告の窓口 | Couchsurfing は運営が秘密の通報を受ける | ホスト自身に関する申告を、当事者でないホストまたは第三者が受ける仕組み（提案 1 の続き） |
| ホストの質のばらつき | Airbnb はホストにも基準と評価がある | ゲストからホストへの評価を集め、ホスト間で見られるようにするか |

## 7. 設計への反映

本書の提案の採否と組み込み方は、[08](08-trouble-measures-roadmap.md) で決め、要件（02）と設計書（03 の版 1.1）に反映した。その過程で、提案 2 は「同じ部屋になる相手」ではなく「同じ夜に家にいるゲスト」と部屋割の話に改めている（部屋の仕切りが敷居だけで、玄関・シャワー・トイレが共用のため）。下の表は、検討を始めた時点の見積もりである。

| 提案 | 変更の大きさ | 必要な変更 |
|---|---|---|
| 1 困ったときの出口 | 小 | 案内画面の文言、「困っています」ボタンと通知、アンケートの欄 |
| 2 同室の相手を選ぶ | 中 | ゲストの性別の登録、夜ごとの設定、申込の選択肢、承認・自動承認の条件、画面 |
| 3 泥酔時の安全 | 小 | 固定のガイドページ、ハウスルールの文言、滞在中の住所表示 |
| 4 カメラとセンサー | 小 | ハウスルールの文言、ガイドの記載 |
| 5 定型項目 | 小 | 初期のハウスルールの文面 |
| 6 警告の段階 | 小 | 「注意」の記録と通知、一覧への表示 |
| 7 実費の請求の予告 | 小 | ハウスルールの文言 |
