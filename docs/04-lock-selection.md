# 04. 鍵の選定

調査日：2026-11-17。前提：ホスト宅の Wi-Fi が使える。

メーカー公式サイトの一部は調査環境から開けなかったため、価格と一部の仕様は報道・比較サイト・公開リポジトリからの情報である。「未確認」と書いた項目は購入前に確かめる。

## 3. SwitchBot の注意点

公開 API のリポジトリに、未解決の報告が 2 件ある。

- **番号の削除が効かない**（2026 年 1 月報告、未解決）：キーパッドタッチで `deleteKey` を呼ぶと成功が返るが、番号は残り、その番号で解錠できてしまう。関係者のコメントによれば、API は命令を送ったことしか確認しておらず、機器が実行したかは分からない。
- **有効期間を読み出せない**（2026 年 3 月報告、未解決）：登録済みの番号一覧に、期限つき番号の開始・終了時刻が含まれない。

C2（即時の無効化）をこのままでは満たせない可能性がある。

## 4. 推奨

**ステージ0 は SwitchBot で始める。ただし、削除に頼らない設計にする。**

理由：月額がかからず、個人で買ってすぐ試せ、発行・遠隔解錠・状態取得は公開 API で足りる。RemoteLOCK は条件への適合は最も確実だが、本体と月額で費用の前提（月 1,000 円程度）を大きく超え、錠前の交換工事も要る。試行段階には重い。

### 設計の変更：番号を短命にする

承認時に朝 10:00 まで有効な番号を出すのではなく、**ゲストが「着きました」を押したときに、30 分だけ有効な番号を出す**。

- 承認を取り消したら、以後は番号を出さない。すでに出した番号も 30 分以内に切れる。削除の成否に左右されない。
- 外出して戻るときは、もう一度「着きました」を押して新しい番号を受け取る。
- 番号を出すのは、その時点で利用が `approved` または `checked_in` のときだけ。
- 削除も併せて呼び、番号一覧を読み直して消えたか確かめる。消えていなければホストに通知する。
- 番号が機器に届くまで数秒〜数十秒かかる見込みなので、画面には「準備中」を出し、届いてから番号を表示する。

この方式は鍵の機種を問わず有効で、設計書（03 の 6.5 節）はこの方式で書いてある。

残る弱点：番号が有効な最大 30 分の間は、取り消した相手でも入れる。より短くする（10 分など）か、その間はホストが玄関を確認する運用で補う。

### 購入後すぐに確かめること

1. 自宅の玄関に取り付けられるか（つまみの形、扉と枠のすき間、キーパッドの設置場所）
2. 期限つき番号を API で発行し、発行から使えるようになるまでの時間
3. 終了時刻を過ぎた番号で解錠できないこと
4. API で削除した番号で解錠できるか（不具合が手元の機種で再現するか）
5. 遠隔の解錠・施錠と状態取得、自動施錠の動作
6. Wi-Fi やハブが止まったとき、発行済みの番号で入れるか

2 と 3 が通れば、短命の番号で運用できる。通らなければ、固定番号＋ホストによる遠隔解錠に切り替えるか、RemoteLOCK を検討する。

### 切り替えの目安

- ステージ2（有償・一般公開）に進むとき
- 短命の番号でも無効化の遅れが問題になったとき
- SwitchBot の検証で 2 または 3 が通らなかったとき

RemoteLOCK を検討する際は、個人での契約可否、API を使えるプランと料金、現行機種と価格を販売元に問い合わせる。
